# 침해 대응 런북 (R17.7)

침해가 의심될 때 **무엇을 어떤 순서로** 하는지. 사고 중에 순서를 고민하지
않기 위해 미리 적는다.

이 문서의 전제 하나: **순서가 내용보다 중요하다.** 폐기를 잘못된 순서로 하면
스스로를 잠가 놓고 나머지를 못 끊는 상황이 된다.

---

## 0. 먼저 (30초)

```
company caps panic --reason "침해 의심"
```

능력 스위치를 전부 끈다. 단계별 인증을 요구하지 않는다 — 킬 스위치에 마찰을
두지 않는 것이 설계다(R8.7). 이것만으로 결제·삭제·DM 이 멈춘다.

**아직 아무것도 폐기하지 마라.** 폐기는 아래 순서대로 한다.

---

## 1. 무엇이 일어났는지 고정 (5분)

```
company verify                    # 원장이 온전한가
company history --kind deny --limit 100
company ops digest                # 오늘 무슨 일이 있었나
```

원장이 손상됐다면 **덮어쓰기 전에 그 상태를 복사해 둔다.** 손상 자체가
증거이고, 백업으로 덮으면 무슨 일이 있었는지 사라진다.

```
cp -r ~/.agentlas-company ~/agentlas-incident-$(date +%Y%m%d-%H%M)
```

---

## 2. 폐기 순서

**바깥에서 안으로.** 공격자가 지금 쓰고 있을 가능성이 높은 것부터 끊되,
우리가 나머지를 끊을 수단은 마지막에 끊는다.

| 순서 | 대상 | 방법 | 왜 이 순서인가 |
|---|---|---|---|
| 1 | 오피스 API 기기 토큰 | `company office device revoke <ID>` | 즉시 반영된다(R14.4). 폰이 탈취됐다면 여기가 가장 빠른 문 |
| 2 | 채널 OAuth 그랜트 | 각 채널 설정에서 앱 연결 해제 | 돈과 평판이 걸린 곳. 아래 개별 절차 참조 |
| 3 | 브라우저 프로필 세션 | `~/.agentlas/chrome-cdp-profile` 삭제 | Hands 가 쓰는 로그인 세션. 채널 그랜트를 먼저 끊어야 재로그인이 막힌다 |
| 4 | 좌석 OAuth | 각 벤더에서 세션 해제 | 마지막이다 — 좌석을 먼저 끊으면 자동 대응 수단을 잃는다 |
| 5 | 오너 계정 2FA | 시드 재발급 | Z0 이므로 이 기계에 없다(R15.7). 폰과 복구코드로 한다 |

### 채널별 그랜트 폐기

- **쓰레드·인스타그램** — Meta 계정센터 → 비즈니스 도구 → 앱 및 웹사이트 →
  연결 해제. 토큰 환경변수(`AGENTLAS_THREADS_TOKEN`)도 함께 지운다
- **네이버** — 네이버 내정보 → 보안설정 → 로그인 기기 관리 → 전체 로그아웃.
  블로그는 API 가 아니라 브라우저 세션이므로 기기 로그아웃이 곧 폐기다
- **유튜브·구글** — 구글 계정 → 보안 → 서드파티 앱 → 액세스 제거
- **카카오** — 카카오계정 → 연결된 서비스 관리

### 폐기 후 확인

```
company security verify          # 구역 권한이 아직 온전한가
company caps                     # 전부 OFF 인가
company office device list       # 활성 기기가 남아 있나
```

---

## 3. 복구

폐기가 끝나기 전에 복구를 시작하지 않는다. 반쯤 끊긴 상태에서 다시 켜면
공격자가 남은 경로로 새 세션을 만든다.

1. 원장 무결성 확인 — `company verify`
2. 손상 구간이 있으면 그 시점 이후를 사람이 읽는다. 자동 복구하지 않는다
3. 좌석 재인증 (벤더별 로그인)
4. 채널 재연결 — **한 번에 하나씩**. 한꺼번에 켜면 무엇이 문제였는지 다시 모른다
5. 능력 스위치는 **켜지 않는다.** 며칠 지켜본 뒤 필요한 것만 짧은 TTL 로

---

## 4. 침해 아님이 확인된 경우

경보가 오탐이었다면 그 사실을 원장에 남긴다 — 다음 사람이 같은 경보를 보고
같은 시간을 쓰지 않도록.

```
company caps on <능력> --ttl 2h --reason "오탐 확인 — <근거>"
```

이상 탐지 임계값이 반복해서 오탐을 낸다면 임계값을 고친다. **경보를 끄지
않는다** — 끈 경보는 켜진 적 없는 경보와 같다.

## 아직 연습하지 않았다

이 런북은 **실전 연습을 거치지 않았다.** Task 17 은 "1회 실전 연습" 을
요구하는데 그것은 실제 계정과 실제 재부팅이 있어야 한다.

연습에서 확인해야 할 것:

- 2번 순서의 채널별 절차가 실제 화면과 맞는가 (UI 는 바뀐다)
- 3번의 좌석 재인증이 구역 분리(`svc-seats`) 아래서 되는가
- 폐기 후 `company ops health` 가 실제로 무엇을 잡는가
- 전체가 몇 분 걸리는가 — 30분을 넘으면 순서를 더 줄여야 한다
