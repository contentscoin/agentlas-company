# Implementation Plan — agentlas-company

각 태스크는 독립적으로 시연 가능해야 하고, 완료 시 요구사항 번호로 추적됩니다.
태스크 1이 완료되기 전에는 런타임 코드를 추가하지 않습니다.

## 2026-08-02 재정의 — company 는 통제, desktop 은 실행

`agentlas-desktop`(v0.9.29, TS/TSX 627개)이 Hands·모바일·Studio·Hub 를 이미 갖고 있다는
사실을 확인했습니다. Task 9~17 은 그걸 모르는 채로 세워졌고, 그대로 두면 전부 다시
만들게 됩니다. **company 의 고유 가치는 통제 계층** — 해시체인 원장, 정책 등급·승인 게이트,
능력 스위치, 오염 추적, 크로스벤더 회의 프로토콜 — 이고 desktop 에 이게 없습니다.
실행 표면은 desktop 것을 씁니다. 설계 §agentlas-desktop 경계 참조.

| 태스크 | 처리 | 근거 |
|---|---|---|
| 9 발행 | **자체 구현 유지** | desktop 에 채널 발행 구현 없음 |
| 10 Hands | **desktop 연동** | 브라우저 CDP 런처 (computer-use 는 macOS 전용 — 8/2 정정) |
| 11 Studio | **범위 축소 — 완료** | 좌석 산출·브랜드 게이트만. 이미지·영상은 표면 부재로 보류 |
| 14 오피스·모바일 | **오피스 API 자체 구현 / 모바일 미해결** | 브리지가 desktop 내부 스토어에 직접 결합 — 8/2 정정 |
| 16 채용 | **desktop 연동 + 선행조건** | Hub 는 있으나 게이트 훅이 desktop 변경을 요구 |
| 17 무인운영 | **자체 구현 — 완료** | 복귀 점검·이상 탐지·요약·런북. 전원 뽑기 연습은 미완 |

연동 범위를 정한 것은 헤드리스 도달성입니다. desktop 기능 대부분이 `electron/ipc.ts` 의
`ipcMain.handle` **486개** 뒤에 있어 Electron 렌더러에서만 호출됩니다. 밖으로 나온 표면은
`mcp-tools/browser-cdp-launcher`(MCP stdio) · `mobile-bridge/server` ·
`browser/approval-server` · `mcp-tools/registry` 이고, 이것이 연동 가능 범위의 전부입니다.
`computer-use/control-server` 도 밖으로 나와 있지만 **macOS 전용**이라 Windows 대상에서는
쓰지 못합니다 (Task 10 항목의 정정 참조).

**8.1 은 Task 14 에서 닫혔습니다** — TOTP 기반 단계별 인증. 아래 주의의 전제가
해소되었으므로 Task 9 의 L3 실물 인증 의존은 더 이상 막혀 있지 않습니다.

**주의 — 순서가 바뀌었습니다.** 이전 권고는 "Task 9 먼저"였습니다. 재정의 후 Task 9 는
Task 10(네이버 블로그 Hands 경로)에 의존하고, L3 비가역 작업인 실제 발행은 8.1 단계별
인증이 자리표시자인 채로 켜면 안 됩니다. 8.1 은 Task 14 에서 해소됩니다.
따라서 **10 → 14 → 9** 가 새 임계 경로입니다.

- [x] 3. 구역과 자격증명 레이아웃 (Windows 적용은 미완 — 아래 참조)
  - `src/zones/layout.ts` — 어떤 경로가 어느 구역 소유인지의 **정본 하나**.
    `icacls` 스크립트와 검증기가 같은 표를 읽는다. 정본이 둘이면 스크립트는

  - `scripts/zones/emit-icacls.mjs` — `.ps1` 을 레이아웃에서 **생성**한다
    (`npm run zones:emit`). 상속을 먼저 끊는다 — 끊지 않으면 부모의 Users
    권한이 남아 아래 규칙이 무의미해진다. 비밀번호는 사람이 입력한다
  - `src/zones/verify.ts` — 판정이 넷이다: `ok`/`violation`/`unknown`/`absent`.
    **확인하지 못한 것을 통과로 보고하지 않는다.** POSIX 는 mode 로 정확히,
    Windows 는 `icacls` 파싱이라 확신 못 하면 `unknown`
  - `src/zones/lint.ts` — 비밀·PII 린트 (R15.5). **`Finding` 에 값을 담을 필드가
    아예 없다** (R15.6) — 담을 곳이 없으면 실수로 담을 수도 없다. 린트 보고서
    자체가 유출 경로가 되는 것을 구조로 막는다. 카드번호는 Luhn 으로,
    주민번호는 생년월일로 확인한다(체크섬은 보지 않는다 — 2020년 10월 이후
    발급분은 뒤 6자리가 임의라 체크섬으로 거르면 진짜를 놓친다)
  - 린트를 발행 브로커에 물렸다. **드라이런에도 적용한다** — 드라이런 출력은
    로그·원장·오너 폰으로 흘러가므로 "실제로 안 나가니까 괜찮다" 가 성립하지 않는다
  - `src/zones/private.ts` — **실측이 찾은 실제 결함을 고쳤다.** company 가 자기
    상태 파일을 `0644` 로 만들고 있었다. 원장·기기 토큰·TOTP 시크릿·능력
    스위치가 전부 월드 리더블이면 구역 분리가 무의미하다. 스크립트로 나중에
    조이는 것에 의존하면 첫 실행부터 스크립트를 돌릴 때까지의 창이 열려 있고,
    하필 그때 그 파일들이 처음 생긴다. 이제 만들 때부터 `0600` 이다
  - 실측: `security verify` 가 `mode 644 — 소유자 외 접근 가능` 4건을 잡았고,
    고친 뒤 **열림 0**. 별도 OS 계정(`seatu`)으로 원장·기기 토큰·TOTP 시크릿을
    읽으려 시도해 **셋 다 거부**됨을 확인 (R15.2). 소유자는 정상 읽힘.
    비밀 섞인 본문의 발행은 드라이런에서도 차단되고 원장에 값이 **0건** 샜다
  - _Requirements: R15.2~R15.8 (R15.1 은 아래 3.2 참조)_

    - 껍데기만 인증 앞에 선다. 브라우저의 첫 요청은 Bearer 토큰을 실을 수
      없다 — 나가는 것은 데이터가 아니라 화면이고, `/api/*` 는 전부 인증 뒤다
    - SSE 만 질의 문자열 토큰을 받는다. `EventSource` 가 헤더를 못 싣기
      때문이고 다른 경로로 넓히지 않는다. 주소창 조각(`#token=`)으로 한 번에
      넣을 수 있게 했다 — 조각은 서버로 가지 않아 접근 기록에 남지 않는다
    - **콘솔을 만들다 찾은 결함: 승인 digest 바인딩이 성립하지 않았다.**
      `decideApproval` 이 카드의 digest 를 꺼내 **카드 자신과** 비교했다.
      승인자의 화면이 비교에 들어가지 않으므로 검사가 언제나 통과한다 —
      R4.5/R4.6 이 요구하는 "승인은 정확한 페이로드에 묶인다" 가 API 경로에는
      없었다. 이제 호출자가 자기가 표시한 digest 를 보내고, 그 사이 대상이
      바뀌었으면 409 로 걸린다. 폰에서 목록을 띄워 둔 채 시간이 지나는 상황이
      정확히 이 경우다. 거부는 digest 를 요구하지 않는다 — 낡은 화면에서 눌러도
      "아니오" 는 아니오이고, 여기서 막으면 오너가 거부하지 못하는 상태가 생긴다
    - 실측: 실물 Chromium(390×844)으로 완주. 조각 토큰 자동 로그인 →
      L2 탭 승인 → L3 코드 없이 거부 → 틀린 코드 거부 → 진짜 TOTP 통과 →
      목록 비움. 페이지 오류 0건. 원장에 `승인 완료 … 인증 없음`,
      `단계별 인증 실패`, `승인 완료 … 인증 통과` 가 순서대로 남았다.
      낡은 digest 로 승인 시도는 409 `digest 불일치` 로 막히는 것까지 확인
    - **원장 타임라인과 실행 상태를 이어서 붙였다 (R10.1~R10.3).** 탭 셋으로
      나뉜다 — 승인 / 실행 / 원장
      - **합성하지 않는다.** 진행률 막대를 그리지 않는다 — 실행이 몇 퍼센트
        남았는지 아는 방법이 없다. 경과 시간과 증거 건수만 보여 준다
      - 원장에는 본문이 없고 요약과 digest 뿐이라는 사실을 화면이 감추지 않는다
      - SSE 로 실시간 추가. `seq` 로 중복을 막고 폰에서 300건까지만 쌓는다
    - **실행 화면을 붙이고 나서 찾은 결함 셋**
      1. **진행 중인 실행이 "0건" 으로 보였다.** 시작·일시정지·완료가 전부
         `decision` 한 종류라 마지막 이벤트의 `kind` 로는 구분되지 않았고,
         막 시작한 실행은 시작 기록 하나뿐이라 종료로 판정됐다. 실제 레시피를
         돌려서 드러났다. 원장 이벤트에 `runPhase`(start/pause/resume/end)를
         두고 그것으로 판정한다 — 요약 문구로 구분하면 문구를 고치는 순간
         깨진다. 표시가 없는 옛 이벤트는 예전 추정으로 되돌아가고, 그 사실을
         `derived: true` 로 함께 내보낸다
      2. **새 필드를 해시가 덮지 않을 뻔했다.** `runPhase` 를 디스크에만 쓰고
         정본(`canonicalize`)에서 빼면 체인을 깨지 않고 실행 상태를 바꿀 수
         있다. 정본에 넣었고, 없는 필드는 예전처럼 빠지므로 **변경 전 이벤트의
         해시는 그대로 검증된다** — 섞인 원장으로 확인했다
      3. **`gate.verdict` 를 전부 붉게 칠했다.** 그 종류는 PASS 도 FAIL 도
         내는데 색을 종류로 정해서 통과가 실패로 보였다. 이제 `deny` 만 붉다
    - **SSE 재연결이 매번 전체를 다시 받았다.** 서버가 `id:` 를 써 보내면서
      재연결 시 `Last-Event-ID` 헤더를 읽지 않았다 — 프로토콜을 반만 구현한
      것이고, 폰이 끊길 때마다 원장 전체가 다시 흘렀다. 헤더를 읽도록 고쳤다
    - 실측: 실물 Chromium 으로 30초짜리 게이트 레시피를 돌리며 관찰.
      실행 탭에 1건(경과 24초, 추정판정 아님) → 원장 항목 6건이 30초 뒤
      9건으로 실시간 증가 → 실행 끝난 뒤 0건. 페이지 오류 0건
    - **지표·복기 화면(측정 탭)까지 붙여 콘솔을 닫았다 (R11.6)**
      - **값을 보관할 곳이 없었다.** 원장에는 요약과 digest 만 남으므로(R9)
        지표와 복기 값이 터미널에 찍히고 사라졌다. `src/metrics/store.ts` 를
        만들어 오너 전용(0600)으로 남긴다
      - **담기는 것은 이미 경계를 넘은 값뿐이다.** 집계값은 브로커가
        화이트리스트로 걸러 좌석까지 내보내는 값이고(R7.6), 막힌 필드와
        미수집은 **이름만**이다 — 이 파일에 새로 노출되는 정보는 없다
      - **실패도 기록한다.** 수집 실패와 설정 미비(토큰 없음)를 남기지 않으면
        화면에서 "측정이 고장 났다" 와 "측정할 일이 없었다" 가 구분되지 않고,
        그 채널이 화면에서 그냥 사라진다
      - **보관소가 없으면 빈 목록이 아니라 "기록 안 켬" 이라고 말한다** —
        측정한 적이 없는 것과 기록을 안 켠 것은 다른 사실이다
      - 감사 기록이 아니라 화면용 캐시다. 종류별 최근 50건만 두고 자른다 —
        감사 기록은 원장이다
    - **측정 화면을 붙이며 고친 낡은 안내**: 복기 제안이 "smartstore
      read_metrics 어댑터가 없으면 복기는 반쪽입니다" 라고 안내했는데 그
      어댑터는 Task 18.2 에서 만들었다. 이미 있는 것을 만들라고 오너를 보내는
      문구였다 — `company metrics --channel …` 로 수집 경로를 확인하라고 고쳤다
    - 실측: 고객 정보가 있는 통계 화면을 실제로 읽어 `orderCount 128 /
      revenue 3,450,000 / refundCount 3` 이 폰 화면에 뜨는 것, 쓰레드가
      `수집 실패 — 토큰이 설정되지 않았다` 로 뜨는 것, 수집이 실패한 복기가
      **`0` 이 아니라 `못 잼`** 으로 뜨는 것을 각각 확인했다. 기록 파일과
      화면 어디에도 고객 이름·연락처·주소가 없다
